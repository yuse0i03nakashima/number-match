# 04 ブラウザ側の構造

対象: `web/js/rules.js`、`game.js`、`render.js`、`main.js`、`web/test/`。

## 4 つの層

| ファイル | 役割 | 状態を持つか |
|---|---|---|
| `rules.js` | ボードの操作。Haskell の `Rules.hs` と同じ関数 | 持たない(純粋) |
| `game.js` | ラン、ステージ、チェーン、ライフ、得点、保存 | 持つ |
| `render.js` | 状態から DOM を作り直す | 持たない |
| `main.js` | 入力を受けて `game` を呼び、返ってきたイベントを `render`、`fx`、`audio` に配る | 少し(アニメ中かどうか) |

Haskell で「純粋な関数」と「IO」を分けたのと同じ考え方です。`rules.js` は引数だけから結果を返し、元の配列を書き換えません(`removePair` は `map` で新しい配列を返します)。

## 判断と見せ方を分ける

`game.js` の各操作は状態を更新したうえで「起きたこと」をイベントの配列で返します。

```js
tap(pos) {
  ...
  if (matches(b[i], b[j]) && connected(b, i, j)) return this.remove(i, j);
  return [{ type: 'invalid', from: prev, to: pos }, { type: 'select', pos }];
}
```

`remove` が返すイベントには、消した位置、得点、チェーン数、消えた行の番号などが入っています。`main.js` はこれを見て、粒子を出す、音を鳴らす、画面を揺らす、と決めます。

この分け方の利点は `game.js` を画面なしで検査できることです。`web/test/game.test.js` は、`localStorage` の代わりにメモリ上の入れ物を渡し、タップ、追加、ヒント、あきらめ、保存と復元を Node だけで通しています。

## 詰みの扱い

消せるペアが無くなっても、ゲームは自分からは教えません。`afterBoardChange` が見るのはクリアだけです。詰んでいることは、プレイヤーが Add か Hint を押したときに分かります。

- Add を押した: 詰んでいれば仕方がないので、チェーンを半分残します。ペアが残っていたのに押した場合は途切れます。
- Hint を押した: 詰んでいれば「まだあると思い込んでいた」ことになるので、使用回数を 1 使い、Chain が半分になり、100 点の減点です。Add も残っていなければ、ここで失敗が確定します。

`useAdd` と `useHint` の先頭で `isStuck`(消せるペアが 0 個か)を見て、この 2 つを分けています。

## 得点

1 Pair の得点は「基礎点 × 難しさ倍率 × Chain 倍率 × Speed 倍率」です。

```js
const pairPoints = Math.round(cfg.score.pairBase * diff.mult * mult * speed.mult * feverMult * hintedRatio);
const rowPoints = Math.round(cfg.score.rowClear * clearedRows.length ** 2 * mult * feverMult);
```

- Chain 倍率は `1 + 1.0 × Chain 数`(上限 ×10)。Chain は「Add を使わずに消した回数」で、Hint で示された Pair を消しても増えません(維持はされます)。
- 難しさ倍率は `scoring.js` の `difficultyMult` が決めます。横の隣どうしは ×1.0、縦 ×1.2、行をまたぐ ×1.5、斜め ×1.5。2 つの間の空マス 1 つごとに +0.25、斜めなら +0.5 です。道の種類は `pathInfo` が調べます。
- スピード倍率は、前の消去からの経過時間で決まります。`tap` が現在時刻を受け取るので、検査では好きな時刻を渡せます。

`heat`(0〜1)は倍率を正規化した値で、演出の強さと色に使います。数値はすべて `config.js` にあります。

## 時間で動くもの

Chain ゲージと FEVER は、タップが無くても時間で進みます。`game.tick(now)` がその役目で、`main.js` が 200 ミリ秒ごとに呼びます。

- Chain ゲージ: 最後に消してから 4 秒は何も起きず、そのあと 1.5 秒ごとに Chain が 1 ずつ減ります。`gaugeRatio(now)` が「次に減るまでの残り」を 0〜1 で返し、HUD の細いバーになります。
- FEVER: 倍率が上限(×10)に達した消去で始まり、10 秒間は得点が 2 倍、Chain は減りません。終わると Chain は半分になります。

`tap` と同じく `tick` も現在時刻を引数で受け取るので、検査では時計を進めるだけで減少や終了を確かめられます。アプリを閉じて戻ったときは `resume(now)` が時刻を今に合わせ直し、離れていた時間ぶん Chain が減ったことにはしません。

## Hint の 3 段階

Hint は Chain 倍率で中身が変わります。`hintTier` が `hint` / `flash` / `scope` を返し、`useHint` がそれに応じて状態を変えます。

- HINT(低倍率): `hintPair` に 1 組を入れます。その Pair を消すと得点は半分で、Chain は増えません。
- FLASH(×4 以上): `flashUntil` に終了時刻を入れ、`lastRemoveAt` をずらしてゲージを半分にします。画面側は `validPairs` の全部を光らせ、`tick` が終了を知らせます。
- SCOPE(×8 以上と FEVER 中): `scope = { tile, misses }` に相手のいるタイルを入れます。`tap` で外れた組にそのタイルが含まれていれば `scopeMiss` が Chain を −3、2 回目で半分にします。`remove` では、そのタイルを含む Pair なら全て獲得で Chain 維持、含まないなら Chain 半分です。

使用上限は Stage ごとに 3 回で、FEVER 中は回数の代わりに FEVER の残り時間を 3 秒払います(`payHint`)。

## お題(quest.js)

Stage ごとに 1 つのお題を出します。種類は Stage 番号から順に選び、その Board で達成できないと分かった種類は飛ばします。

- 「X を最初に消し切れ」: 最初に Board から消え切る数字が X であること。達成できるかは、`solver.js` の `solve` に手の制限(`allow`)を渡して調べます。X より先に別の数字が消え切る手を使わずに全消しできれば出します。
- 「Chain を途切れさせずに N 回消せ」: Chain が伸びた手だけを数え、Add・ゲージの減り・SCOPE の 2 回目の失敗で 0 に戻します。Hint で消した手は Chain が伸びないので数えません。
- 「斜めで N 回消せ」: 最初の Board に斜めの Pair が N 組以上あるときだけ出します。
- 「Hint を使わずに Clear」: いつでも出せます。

進み具合の更新は `updateQuest` の純粋な関数で、game.js は手のあとに呼んで `quest` イベントを出すだけです。達成すると Clear 時に +500 が加わります。

World の終わりには、その World で残した Add の回数を数え、次の World の開始 Chain(1 回ごとに +1、上限 +5)と Heart(3 回ごとに +1)に変えます。Perfect の回復を先に入れ、Heart の上限 3 を超える分は捨てます。

## 感想戦(review.js)

Stage が終わると、手の記録(`history`)を読んで各手を評価できます。評価は `review.js` の純粋な関数で、画面とは分かれています。

- 悪手(✖): その手で「Add なしでは全消しできない Board」になった。別の手なら続けられたのに。`solver.js` の探索で、その手のあとの Board が解けるかを調べます。Pair が残っているのに Add を押して Chain を切った手も悪手です。
- 逃した(△): 同じ局面でもっと高い得点の手があった(行消し、DIGIT CLEAR、難しい道)。差が 100 点以上で 1.5 倍以上のときだけ。
- 最善(★): 全消しを保つ手の中で得点が最大の手を選んでいた。
- 良手(○): それ以外。

得点の見積もりは game.js と同じ式から Speed と FEVER を除いたものです。人の速さは局面の評価に含めません。探索は予算つきなので、大きな Board では「解けない」と厳しめに出ることがあります。

## Add が尽きたあと

ADD ボタンは GIVE UP に変わります。`useAdd` は Add が残っていなければ `giveUp` を呼び、Heart を 1 つ減らしたうえで Stage 得点の半分を残します。消せる Pair も無いのに Hint を押した場合(気づいていなかった)は、Stage 得点を全部失い、さらに 300 点を引いて失敗になります。どちらも `stageFailed(reason, keepRatio)` の `keepRatio` の違いです。

## 保存

`localStorage` に、進行(`progress`: 到達ステージ、星、再挑戦の回数、ベスト)と、遊んでいる途中のラン(`run`)を JSON で保存します。アプリを閉じても「つづきから」で戻れます。読み書きは `try` で包んであり、使えない環境でも落ちません。

## DOM を作り直す描き方

`render.js` の `renderBoard` は、ボードが変わるたびにマスの要素を全部作り直します。差分だけ更新する書き方より単純で、ボードは多くても 100 マス程度なので速度は問題になりません。

消えるマスのアニメは作り直す前に `removing` クラスを付け、CSS のアニメが終わる 180 ミリ秒を待ってから作り直します。`main.js` の `onRemove` が `await sleep(180)` で待っているのはそのためです。待っている間はタップを受け付けないよう `busy` で止めます。

## ルールの検査

`web/test/rules.test.js` は Haskell が書き出した `vectors.json` を読み、40 個のボードそれぞれで `validPairs`、`removePair` と `collapseRows`、`addNumbers` の結果が一致することを確かめます。

ルールを変えるときの手順は、Haskell を直す、`cabal test` を通す、`cabal run gen` でベクタを作り直す、JavaScript を直す、`node --test` を通す、の順です。

## 演習

1. `tap` で、同じマスを 2 回押したときに何が起きるか、コードから読み取る。
2. チェーンが切れるのを「追加」だけにし、ヒントでは切れないようにする。どの関数を変えればよいか。
3. `game.test.js` に「追加を使い切って詰むと `stageFailed` が返る」検査を足す。ボードを小さい配列に差し替える方法は既存の検査にある。
