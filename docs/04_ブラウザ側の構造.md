# 04 ブラウザ側の構造

対象: `web/js/rules.js`、`game.js`、`render.js`、`main.js`、`web/test/`。

## 4 つの層

| ファイル | 役割 | 状態を持つか |
|---|---|---|
| `rules.js` | 盤面の操作。Haskell の `Rules.hs` と同じ関数 | 持たない(純粋) |
| `game.js` | ラン、ステージ、チェーン、ライフ、得点、保存 | 持つ |
| `render.js` | 状態から DOM を作り直す | 持たない |
| `main.js` | 入力を受けて `game` を呼び、返ってきたイベントを `render`、`fx`、`audio` に配る | 少し(アニメ中かどうか) |

Haskell で「純粋な関数」と「IO」を分けたのと同じ考え方です。`rules.js` は引数だけから結果を返し、元の配列を書き換えません(`removePair` は `map` で新しい配列を返します)。

## 判断と見せ方を分ける

`game.js` の各操作は状態を更新したうえで「起きたこと」をイベントの配列で返します。

```js
tap(pos) {
  ...
  if (matches(b[i], b[j]) && connected(b, i, j)) return this.remove(i, j);
  return [{ type: 'invalid', from: prev, to: pos }, { type: 'select', pos }];
}
```

`remove` が返すイベントには、消した位置、得点、チェーン数、消えた行の番号などが入っています。`main.js` はこれを見て、粒子を出す、音を鳴らす、画面を揺らす、と決めます。

この分け方の利点は `game.js` を画面なしでテストできることです。`web/test/game.test.js` は、`localStorage` の代わりにメモリ上の入れ物を渡し、タップ、追加、ヒント、あきらめ、保存と復元を Node だけで通しています。

## 詰みの扱い

消せるペアがなくなっても、ゲームは自分からは教えません。`afterBoardChange` が見るのはクリアだけです。詰んでいることは、プレイヤーが追加かヒントを押したときに分かります。

- 追加を押した: 詰んでいれば仕方がないので、チェーンを半分残します。ペアが残っていたのに押した場合は途切れます。
- ヒントを押した: 詰んでいれば「まだあると思い込んでいた」ことになるので、使用回数を 1 使い、チェーンが半分になり、100 点の減点です。追加も残っていなければ、ここで失敗が確定します。

`useAdd` と `useHint` の先頭で `isStuck`(消せるペアが 0 個か)を見て、この 2 つを分けています。

## 得点

1 ペアの得点は「基礎点 × 難しさ倍率 × チェーン倍率 × スピード倍率」です。

```js
const pairPoints = Math.round(cfg.score.pairBase * diff.mult * mult * speed.mult * feverMult * hintedRatio);
const rowPoints = Math.round(cfg.score.rowClear * clearedRows.length ** 2 * mult * feverMult);
```

- チェーン倍率は `1 + 1.0 × チェーン数`(上限 ×10)。チェーンは「追加を使わずに消した回数」で、ヒントで示されたペアを消しても増えません(維持はされます)。
- 難しさ倍率は `scoring.js` の `difficultyMult` が決めます。横の隣どうしは ×1.0、縦 ×1.2、行をまたぐ ×1.5、斜め ×1.5。2 つの間の空マス 1 つごとに +0.25、斜めなら +0.5 です。道の種類は `pathInfo` が調べます。同じファイルの `sightLines` は、選んだマスから縦・斜め・読み順に目を走らせて、途中の空マスと最初にぶつかる数字を返します。`render.js` がそれらのマスに薄い枠を付けるので、斜めの道が見やすくなります。相手が合うかどうかは見ないので、答えを教えることにはなりません。
- スピード倍率は、前の消去からの経過時間で決まります。`tap` が現在時刻を受け取るので、テストでは好きな時刻を渡せます。

`heat`(0〜1)は倍率を正規化した値で、演出の強さと色に使います。数値はすべて `config.js` にあります。

## 時間で動くもの

チェーンゲージと FEVER は、タップがなくても時間で進みます。`game.tick(now)` がその役目で、`main.js` が 200 ミリ秒ごとに呼びます。

- チェーンゲージ: NORMAL では最後に消してから 6 秒は何も起きず、そのあと 2.5 秒ごとにチェーンが 1 ずつ減ります(HARD は猶予 4 秒、1.5 秒ごと)。`gaugeRatio(now)` が「次に減るまでの残り」を 0〜1 で返し、HUD の細いバーになります。
- FEVER: 倍率が上限(×10)に達した消去で始まり、10 秒間は得点が 2 倍、チェーンは減りません。終わるとチェーンは半分になります。

`tap` と同じく `tick` も現在時刻を引数で受け取るので、テストでは時計を進めるだけで減少や終了を確認できます。アプリを閉じて戻ったときは `resume(now)` が時刻を今に合わせ直し、離れていた時間ぶんチェーンが減ったことにはしません。

## ヒントの 3 段階

ヒントはチェーン倍率で中身が変わります。`hintTier` が `hint` / `flash` / `scope` を返し、`useHint` がそれに応じて状態を変えます。

- HINT(低倍率): `hintPair` に 1 組を入れます。そのペアを消すと得点は半分で、チェーンは増えません。
- FLASH(×4 以上): `flashUntil` に終了時刻を入れ、`lastRemoveAt` をずらしてゲージを半分にします。画面側は `validPairs` の全部を光らせ、`tick` が終了を知らせます。
- SCOPE(×8 以上と FEVER 中): `scope = { tile, misses }` に相手のいるタイルを入れます。`tap` で外れた組にそのタイルが含まれていれば `scopeMiss` がチェーンを −3、2 回目で半分にします。`remove` では、そのタイルを含むペアならそのまま獲得してチェーンを維持し、含まないならチェーンを半分にします。

使用上限はステージごとに 3 回で、FEVER 中は回数の代わりに FEVER の残り時間を 3 秒払います(`payHint`)。

## お題(quest.js)

ステージごとに 1 つのお題を出します。種類はステージ番号から順に選び、その盤面で達成できないと分かった種類は飛ばします。

- 「X を最初に消し切れ」: 最初に盤面から消え切る数字が X であること。達成できるかは、`solver.js` の `solve` に手の制限(`allow`)を渡して調べます。X より先に別の数字が消え切る手を使わずに全消しできれば出します。
- 「チェーンを途切れさせずに N 回消せ」: チェーンが伸びた手だけを数え、追加・ゲージの減り・SCOPE の 2 回目の失敗で 0 に戻します。ヒントで消した手はチェーンが伸びないので数えません。
- 「斜めで N 回消せ」: 最初の盤面に斜めのペアが N 組以上あるときだけ出します。
- 「ヒントを使わずにクリア」: いつでも出せます(CLASSIC と Hint 0 の GAMBIT では除外します)。

進み具合の更新は `updateQuest` の純粋な関数で、`game.js` は手のあとに呼んで `quest` イベントを出すだけです。達成するとクリア時に +500 が加わります。

ワールドの終わりには、そのワールドで残した追加の回数を数え、次のワールドの開始チェーン(1 回ごとに +1、上限 +5)とライフ(3 回ごとに +1)に変えます。Perfect の回復を先に入れ、ライフの上限 3 を超える分は捨てます。

## 感想戦(review.js)

ステージが終わると、手の記録(`history`)を読んで各手を評価できます。評価は `review.js` の純粋な関数で、画面とは分かれています。

- 悪手(✖): その手で「追加なしでは全消しできない盤面」になった。別の手なら続けられたのに。`solver.js` の探索で、その手のあとの盤面が解けるかを調べます。ペアが残っているのに追加を押してチェーンを切った手も悪手です。
- 逃した(△): 同じ局面でもっと高い得点の手があった(行消し、DIGIT CLEAR、難しい道)。差が 100 点以上で 1.5 倍以上のときだけ。
- 最善(★): 全消しを保つ手の中で得点が最大の手を選んでいた。
- 良手(○): それ以外。

得点の見積もりは `game.js` と同じ式からスピードと FEVER を除いたものです。人の速さは局面の評価に含めません。探索は予算つきなので、大きな盤面では「解けない」と厳しめに出ることがあります。

## 追加が尽きたあと

ADD ボタンは GIVE UP に変わります。`useAdd` は追加が残っていなければ `giveUp` を呼び、ライフを 1 つ減らしたうえでステージ得点の半分を残します。消せるペアもないのにヒントを押した場合(気づいていなかった)は、ステージ得点を全部失い、さらに 300 点を引いて失敗になります。どちらも `stageFailed(reason, keepRatio)` の `keepRatio` の違いです。

## 3 つのモード

`game.js` は `mode`(`normal` / `classic` / `hard`)と、モードごとの枠 `slots` を持ちます。枠には記録(`progress`)と進行中のランが入り、`game.progress` と `game.run` はいまのモードの枠を返します。タイトルのタブで `setMode` を呼ぶと枠が切り替わるだけなので、片方で遊びかけのランがあっても、ほかのモードの記録は変わりません。

CLASSIC の違いは `game.classic` の分岐で書いています。倍率を返す `multiplierFor` は 1 を返し、`hintTier` は常に `hint`、`tick` のゲージの減りと `remove` のスピードと FEVER の開始は飛ばします。`afterBoardChange` はクリアに加えて詰みも見て、追加が残っていれば `deadEnd` イベント、なければ `stageFailed` を返します。`stageFailed` は CLASSIC ではライフを減らしません。

## VS(2 台で同じ盤面)

VS は、2 台のスマホで同じ盤面を同時に遊び、制限時間内の得点を競う遊び方です。片方が部屋を作ると 4 文字の合言葉が出て、もう片方がその合言葉で入ると 2 台がつながります。部屋を作った側がワールドと制限時間を選んで START を押すと、両方の画面で 3・2・1 のあと同じ盤面が出ます。

通信は `vs.js` にまとめました。2 台は WebRTC のデータチャネルで直接つながり、相手を見つける仲介だけ PeerJS の公開サーバーを使います。つながったあとはサーバーを使いません。盤面は部屋を作った側が選び、マスの並びをそのまま相手に送るので、2 台が持つ面データが同じでなくても同じ盤面になります。

進行中は `main.js` の `game` を VS 用の `Game` に差し替えます。この `Game` は面データを 1 ステージぶんだけ持ち、保存先を持たないので、通常の記録やコインには触れません。ルールは NORMAL と同じで、チェーン倍率と FEVER が効く一方、ライフ、コイン、ショップ、必殺技はありません。追加が尽きると ADD ボタンは FINISH になり、押すとその時点の得点で終わりです。得点が確定するのは、制限時間が来たとき、盤面を全部消したとき(残り 1 秒ごとに加点)、FINISH を押したときの 3 つです。相手の得点と倍率と残りマス数は 0.4 秒ごとに送り合い、盤面の上の帯に出します。両方の得点が確定すると勝敗の画面になり、部屋を作った側は REMATCH で新しい盤面を配れます。

スマホの回線によっては 2 台が直接つながらないことがあり、その場合は合言葉の部屋が見つからないか、つないでいるまま止まります。同じ Wi-Fi にするか、片方をモバイル回線からテザリングに切り替えると通ることが多いです。

## コイン・ショップ・スロット

コインは `game.coins` にあり、モードの枠の外にあります。`stageClear` でステージの得点を足し、`buy` と `addCoins` で減らします。ショップの品物と値段は `config.js` の `shop` にモードごとに書き、`shopItems` が「いま買えるか」(残りが 0 で、コインが足りる)を返します。買った追加とヒントは `addsBought` と `hintsBought` に数え、温存ボーナスと投資からは引きます。

スロットは `slot.js`(判断)と `slotview.js`(画面)に分かれています。`Slot.start` で役を先に抽選し、`Slot.stop(k, pressed)` が引き込みを入れた停止位置を返します。役なしの回は最後のリールで何も揃わない位置を選び、役ありの回で 2 本目を止めるときは、残りのリールをでたらめに押しても揃う割合(`coverage`)が最も高い位置を選びます。`simulate` は押し方(でたらめ・完璧)を変えて払い戻し率を測る関数で、確率の調整に使います。画面は毎フレーム「中段のコマ番号」を進め、止めるときは決まった位置まで回してから止めるので、引き込みのぶんだけ滑って見えます。

## デイリーボーナス

タイトルを開くと、その日まだ受け取っていなければ DAILY BONUS のボタンが出ます。押すとコインが増えます。額は何日目かで変わり、`config.js` の `daily.rewards` に 1 日目から 7 日目までの額(300、400、500、600、800、1000、1500)を書いています。前の日にも受け取っていれば日数が進み、1 日あくと 1 日目に戻ります。7 日目の次は 1 日目です。

日付の区切りは朝 4 時です(`daily.resetHour`)。0 時で区切ると、夜に遊ぶ人が 0 時をまたいで 2 回受け取れるためです。判断は `game.js` の `dailyStatus` と `claimDaily` にあり、最後に受け取った日(年-月-日の文字列)と連続日数を保存に入れています。テストは `test/daily.test.js` にあります。

## HARD モードと GAMBIT

タイトルの HARD タブで遊べる、NORMAL の高難易度版です。NORMAL で 30 ステージ(ワールド 6 まで)をクリアすると開放され、記録は NORMAL と別の枠に入ります。代償は追加 1 回、ライフ 2、ヒント 2 回、チェーンの減りが速いこと(猶予 4 秒、そのあと 1.5 秒ごとに 1 減る)で、見返りは得点 2 倍(ランクの基準も 2 倍)と、クリアで貯まるコイン 3 倍です。値は `config.js` の `hard` にまとめています。

HARD の設定は `game.js` の `cfg` が組み立てます。NORMAL と CLASSIC では渡された `CONFIG` をそのまま返し、HARD のときだけ `gambit.js` の `hardConfig` で `hard.rules` と選んだ GAMBIT の書き換えを順に当て、得点の項目に `pointMult` を掛けたものを返します。ゲームの他の部分は `this.cfg` を読むだけなので、HARD のための分岐はほとんど要りません。追加の回数とコインの倍率だけは `startStage` と `stageClear` で `cfg.hard` を見ます。

GAMBIT はワールドの始めに 3 枚から 1 枚選ぶ札です。見返りと代償が対になっていて、そのワールドの 5 ステージの間だけ有効です。札は 8 種類で、`gambit.js` の `GAMBITS` に名前、見返り、代償、設定の書き換え(`patch`)を持ちます。BLAZE は FEVER の長さを 2 倍にしてヒントを 0 に、GLASS はコインをさらに 2 倍にしてライフを 1 に、RESERVE は各ステージの追加を +2 してコインを半分にします。3 枚はランの回数とステージ番号を種にして選ぶので、同じランの同じワールドでは同じ 3 枚が出ます。選ぶと `chooseGambit` が今のステージの追加とヒント(まだ使っていなければ)とライフの上限にすぐ反映し、ワールドが終わると `startStage` が札を外して次の 3 枚を出します。

## 保存

`localStorage` に、進行(`progress`: 到達ステージ、スター、再挑戦の回数、ベスト)と、遊んでいる途中のラン(`run`)を JSON で保存します。アプリを閉じても Continue で戻れます。読み書きは `try` で包んであり、使えない環境でも落ちません。

## DOM を作り直す描き方

`render.js` の `renderBoard` は、盤面が変わるたびにマスの要素を全部作り直します。差分だけ更新する書き方より単純で、盤面は多くても 100 マス程度なので速度は問題になりません。

消えるマスのアニメは作り直す前に `removing` クラスを付け、CSS のアニメが終わる 180 ミリ秒を待ってから作り直します。`main.js` の `onRemove` が `await sleep(180)` で待っているのはそのためです。待っている間はタップを受け付けないよう `busy` で止めます。

## ルールのテスト

`web/test/rules.test.js` は Haskell が書き出した `vectors.json` を読み、40 個の盤面それぞれで `validPairs`、`removePair` と `collapseRows`、`addNumbers` の結果が一致することを確認します。

ルールを変えるときの手順は、Haskell を直す、`cabal test` を通す、`cabal run gen` でベクタを作り直す、JavaScript を直す、`node --test` を通す、の順です。
