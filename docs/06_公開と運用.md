# 06 公開と運用

対象: `.github/workflows/pages.yml`、`web/manifest.json`、`web/sw.js`。

## GitHub Pages で配る

`web/` の中身をそのまま置けば動く静的サイトなので、GitHub Pages で配ります。公開 URL は https://yuse0i03nakashima.github.io/number-match/ です。

Pages は「ブランチのルート」か「ブランチの docs/」しか直接配信できません。そこで `web/` の中身だけを取り出した `gh-pages` ブランチを作り、Pages の配信元をそのブランチに設定しています。`web/` を変えてコミットしたら、リポジトリのルートで次を実行すると `gh-pages` が更新されます。

```powershell
powershell -ExecutionPolicy Bypass -File tools/deploy.ps1
```

中では `git subtree split --prefix web main` で `web/` だけの履歴を切り出し、それを `gh-pages` に強制 push しています。反映まで 1 分ほどかかります。

GitHub Actions で自動配置する定義は `tools/pages.yml` に置いてあります。`gh` の認証に workflow スコープがなく、Actions の定義を push できなかったため、今は使っていません。使うときは `gh auth refresh -h github.com -s workflow` を実行してから、このファイルを `.github/workflows/pages.yml` に移します。

## スマホで開く

URL をスマホの Chrome か Safari で開き、「ホーム画面に追加」を選ぶとアイコンが置かれます。`manifest.json` が名前、アイコン、縦向き固定、全画面表示を指定しています。

`sw.js`(Service Worker)は一度開いたファイルを端末に保存し、電波がなくても起動できるようにします。「ネットワーク優先、失敗したら保存済み」の方針なので、更新があれば取り込み、なければ手元のものを使います。ファイルを足したり名前を変えたりしたときは、`sw.js` の一覧と `VERSION` の更新が必要です。

## 面を作り直す

```powershell
cd generator
cabal run gen
```

`web/levels/stages.json` と `web/test/vectors.json` が上書きされます。そのあとリポジトリのルートで `node --test web/test/*.test.js` を実行し、13 件が通ることを確かめてから push します。

ステージの構成を変えるのは `Generate.hs` の `stageSpec` です。マス数は偶数にします。今は `24 + 2 × ステージ番号` です。

## 調整の場所

| 変えたいこと | 場所 |
|---|---|
| 得点、倍率、ライフ、演出の量 | `web/js/config.js` |
| ステージごとのマス数と追加の回数 | `generator/src/NumberMatch/Generate.hs` の `stageSpec` |
| ステージ数、探索の予算 | `generator/app/Main.hs` の `stageCount`、`budget` |
| 色とフォント | `web/css/style.css` の `:root` |
| 効果音 | `web/js/audio.js` の各メソッド |

## 保存データ

進行は端末の `localStorage` に `numbermatch.v1` という鍵で入っています。端末ごとに別で、サーバーには何も送りません。消したいときはブラウザのサイトデータを削除します。
