# 03 盤面を生成する

対象: `generator/src/NumberMatch/Generate.hs`、`Json.hs`、`app/Main.hs`。
対応する授業の章: 第 4 章(`iterate`、`take`)、第 7 章(レコード構文)、第 11 章 入出力(予習)。

## 乱数を自分で書く

ライブラリの乱数を使わず、線形合同法という古典的な式で書いています。

```haskell
nextSeed s = (1103515245 * s + 12345) `mod` 2147483648
digitFrom s = (s `div` 65536) `mod` 9 + 1
```

`nextSeed` は整数を受け取って次の整数を返す純粋な関数です。同じ数を入れれば必ず同じ数が出ます。乱数らしく見えるのは、掛けて足して割った余りを取ると、元の数との関係が人目には追えなくなるからです。

純粋だから、盤は「シード」1 つで再現できます。`stages.json` に盤の数字を全部書く代わりにシードだけ書いても同じ盤を作れますし、不具合の報告で「シード 1279878006 の盤」と言えば同じ状況を再現できます。

```haskell
randomDigits seed n = map digitFrom (take n (drop 1 (iterate nextSeed seed)))
```

`iterate nextSeed seed` は `[seed, nextSeed seed, nextSeed (nextSeed seed), ...]` という無限リストです。第 4 章で見た `take` で必要な個数だけ取り出します。遅延評価のおかげで、無限リストを書いても必要な分しか計算されません。

`digitFrom` で `div 65536` しているのは、線形合同法の下位ビットが規則的に並ぶ癖があるからです。上位のビットを使うと偏りが減ります。

## ステージの設定

```haskell
data StageSpec = StageSpec
  { specStage :: Int
  , specCells :: Int
  , specAdds  :: Int
  }
```

第 7 章のレコード構文です。`specCells spec` のように名前で取り出せます。`stageSpec n` がステージ番号から設定を返します。マス数はステージが進むごとに 2 ずつ増え(ステージ 1 が 26 個、ステージ 30 が 84 個)、追加の回数はステージ 11 から 2 回に減ります。

マス数は必ず偶数です。奇数だと追加なしで全消しできないからです(01 のパリティ不変量)。最初は本家に合わせて 3 行(27 個)にしていて、生成器が 1 面も見つけられずに止まりました。パリティ条件を満たす 27 マスの盤が存在しないので当然ですが、気づくまでに時間がかかりました。

## 面を見つける

```haskell
findStage spec seed
  | parityOk b, enoughMoves, Just sol <- solve budget 0 b = Stage spec seed b 0 moves sol
  | otherwise = findStage spec (nextSeed seed)
  where
    b     = randomBoard seed (specCells spec)
    moves = length (validPairs b)
```

シードから盤を作り、条件を満たせば採用、満たさなければ次のシードで試します。ガードの順番に意味があります。`parityOk` は一瞬で判定でき、ランダムな盤の 31/32 を弾く軽い検査です。`enoughMoves`(初手で消せる組の数)も軽い検査です。重い `solve` は最後に置き、軽い検査を通った盤だけに使います。

`Just sol <- solve budget 0 b` はパターンガードという書き方で、`solve` の結果が `Just` のときだけ条件が成立し、中身を `sol` に束縛します。

各ステージで 3 枚の盤を作ります。失敗して再挑戦するときに別の盤を出すためです。開始シードを 104729 ずつずらして、互いに違う盤になるようにしています。

## JSON を手で組み立てる

JSON のライブラリ(aeson)は使わず、文字列を結合して作っています。

```haskell
jList xs = Json ("[" ++ intercalate "," (map render xs) ++ "]")
jObj kvs = Json ("{" ++ intercalate "," [show k ++ ":" ++ render v | (k, v) <- kvs] ++ "}")
```

整数のリストを `show` すると `[1,2,3]` になり、これはそのまま JSON です。文字列も `show` でほぼ JSON の形になります(ASCII の範囲なら同じ)。この 2 つを組み合わせるだけなので、ライブラリを入れる手間より小さく済みます。

`newtype Json = Json String` は、「JSON として組み立て済みの文字列」をただの `String` と区別するための型です。実行時のコストはありません。

## IO は Main.hs に閉じ込める

ファイルを書く、引数を読む、進み具合を表示する。こうした副作用のある処理は `app/Main.hs` にだけあります。

```haskell
main = do
  args <- getArgs
  hSetEncoding stdout utf8
  hSetBuffering stdout LineBuffering
  let stages = map stageVariants [1 .. stageCount]
  mapM_ (mapM_ report) stages
  writeFile (outDir ++ "/levels/stages.json") (render (jList (map stageJson stages)))
```

`do` 記法とモナドは第 11 章で習います。今の段階では、「`do` の中の行は上から順に実行される」「`<-` で結果を受け取る」と読めば十分です。

`hSetBuffering stdout LineBuffering` は、出力先がファイルやパイプのとき 1 行ずつ表示させる指定です。これがないと出力が溜め込まれ、生成が終わるまで何も表示されません。最初の実行で「止まっているのか動いているのか分からない」状態になったのは、これが原因でした。
