# 00 全体像

このプロジェクトで何を作り、どう分担しているかを説明します。コードを読む前の見取り図です。

## 何を作ったか

家族が遊んでいる Number Match は広告が多い。そこで同じルールのゲームを自作し、広告なしでスマホのブラウザから遊べるようにしました。本家との違いは次の 4 点です。

- 演出を派手にした。消すと粒子が飛び、行が消えると画面が揺れる。
- 緊張感を足した。チェーン倍率、追加の回数制限、ライフ制、星評価。
- すべての面が数字を追加せずに全消しできる。本家にはこの保証がない。
- 本人の学習教材を兼ねる。ルールと生成は Haskell、画面は JavaScript で書き、解説を添える。

## ルール(本家と同じ部分)

- ボードは幅 9 の格子。数字は 1 から 9。
- 同じ数字か、たして 10 になる 2 つを選ぶと消える。
- 2 つは、縦・横・斜めの直線上か、読み順(行の終わりから次の行の始まりへ続く)で並んでいて、間のマスがすべて空であること。
- 1 行が全部空になると、その行はボードから消える。
- 「追加」を押すと、残っている数字を読み順のままボードの末尾に書き足す。
- ボードが空になればステージクリア。

## 緊張感の設計

桜井政博氏が繰り返し述べている「リスクとリターン」を軸にしました。プレイヤーが自分で選べる損得の対を用意し、時間制限は置かず、失敗しても回復の手段を残します。

| 要素 | リスク | リターン |
|---|---|---|
| Chain 倍率 | Add を使うと途切れて ×1.0 に戻る。6 秒消さないでいると 2.5 秒ごとに 1 段階減る(ゲージ) | 1 Pair 消すごとに +1.0、上限 ×10(9 連鎖)。Pair の得点にも行消しの得点にも掛かり、熱くなるほど演出が強い |
| FEVER | 終わると Chain が半分になる | 倍率が ×10 に達すると 10 秒間 Score ×2。その間 Chain は減らず、Pair を 1 つ消すごとに残り時間が 1.5 秒延びる(全体で 25 秒まで)。演出も最も派手になる |
| Add(ステージごとに 2〜3 回) | ペアが残っているのに使うとチェーンが途切れ、ボードが増える。詰んでから使えばチェーンは半分残る | 消せるペアが生まれて詰みを回避できる |
| Hint(使用上限 3 回) | HINT: 示された Pair は得点半分。FLASH: ゲージが半分になる。SCOPE: 相手を外すと Chain −3、2 回目で半分、光ったタイルを使わず別を消しても半分。Dead End なのに押すと Chain 半分と −100 | Chain は途切れない。HINT は Pair を 1 組、FLASH(×4 以上)は全 Pair を 1.2 秒、SCOPE(×8 以上と FEVER)は相手のいるタイルを 1 枚示す。残した回数は Clear 時 +50 |
| 難しい消し方 | なし | Pair の得点に倍率が掛かる。縦 ×1.2、行をまたぐ ×1.5、斜め ×1.5。2 つの間の空マス 1 つごとに +0.25、斜めなら +0.5 |
| スピード | なし | 前の消去から 2.2 秒以内で ×1.2、1 秒以内で ×1.5(ペアの得点だけ)。速いほど演出も強い |
| Heart(3 つ) | Add が尽きると ADD ボタンが GIVE UP になる。押すと 1 つ減るが Stage 得点の半分は残る。気づかずに Hint を押すと 1 つ減り、Stage 得点を全部失い、さらに 300 点の減点。0 で Run 終了 | Add なしで Clear すると 1 つ回復する |
| 行消し | なし | 100 点 × 同時に消えた行数の 2 乗 × 倍率。連続で行を消すと演出が段階的に強くなる |
| DIGIT CLEAR | なし | ある数字(たとえば 3)を Board から全部消し切ると、1 つの数字ごとに +150 × Chain 倍率。「どの数字から片付けるか」の計画に報酬を与える |
| ALL CLEAR | なし | Board を全部消すと +200(Add なしなら Perfect +500 と Heart 回復)。Chain と FEVER はそのまま次の Stage へ続く。Result の画面は World(5 Stage)の終わりだけ |
| Star と Rank | なし | Add 0 回で ★★★、1 回で ★★。Stage 得点が基準点(マス数 × 50)の 2 倍以上で S、1.4 倍で A、0.9 倍で B。Title に World ごとの Rank が並ぶ |
| Add 温存と投資 | 温存しすぎて詰むと GIVE UP になる | Clear 時、使わずに残した Add 1 回ごとに +150。さらに World(5 Stage)で残した回数が次の World に持ち越され、1 回ごとに開始 Chain +1(上限 +5)、3 回ごとに Heart +1(上限 3 まで)になる |
| Quest(お題) | なし | Stage ごとに 1 つ出る。「3 を最初に消し切れ」「Chain を途切れさせずに 7 回消せ」「斜めで 2 回消せ」「Hint を使わずに Clear」の 4 種類。達成で +500。出す前に、その Board で達成できる手順があることを探索で確かめる |

Relax モード(Title かメニューで切り替え)では、時間の要素を外します。Chain のゲージは減らず、Speed の倍率も付きません。BGM はテンポを 124 から 96 に落として層を 2 つまでにし、FEVER 中も静かなまま、粒子と揺れも半分ほどにします。得点と Star の基準は通常と同じです。

ラン終了後は、5 ステージごとの「ワールド」の先頭から再開します。最初からやり直すのは重すぎ、同じステージからすぐ再開すると緊張感がなくなるため、その中間を取りました。

## 分担

```
generator/ (Haskell)                    web/ (JavaScript)
  Board.hs    ボードの型                      rules.js   Rules.hs の移植(関数名も同じ)
  Rules.hs    消せるペア・行の縮約・追加      game.js    ラン・ステージ・得点・保存
  Solver.hs   全消し手順の探索              render.js  DOM の描き直し
  Generate.hs 乱数とボードの生成               fx.js      Canvas の演出
  Json.hs     JSON の書き出し              audio.js   WebAudio の効果音
  app/Main.hs 面データとテストベクタを出力   main.js    入力と各部品のつなぎ
         │                                      ▲
         └── stages.json / vectors.json ────────┘
```

Haskell は「面を作る」側で、遊ぶときには動きません。遊ぶときに動くのは JavaScript だけです。この分け方にした理由は 2 つあります。Haskell をブラウザで動かす仕組み(WASM バックエンド)がこの PC の Windows では使えないこと、そして演出のような細かい画面制御は JavaScript のほうが書きやすいことです。

ルールは Haskell 側を基準にします。`Rules.hs` の各関数をそのまま JavaScript に移し、Haskell が書き出した 40 個のテストベクタと一致することを `node --test` で確かめます。どちらかを変えたら、もう一方も変えて検査を通します。

## 先に知っておく発見

27 マスのボードは追加なしでは絶対に全消しできません。1 手で 2 マスずつ消えるので、全消しできるボードのマス数は偶数に限られるからです。本家が 27 個(3 行)で始まるのは、追加を前提にした設計だからでしょう。このゲームでは 26 個(2 行と 8 個)から始めます。詳しくは 01 で扱います。
