# 01 ルールを型で書く

対象: `generator/src/NumberMatch/Board.hs`、`Rules.hs`。
対応する授業の章: 第 4 章(リスト内包表記)、第 5 章(再帰)、第 6 章(高階関数)、第 7 章(型と型クラスの宣言)。

## 盤を 1 本のリストで表す

Number Match の盤は幅 9 の格子ですが、ここでは読み順(左から右、上から下)に並べた 1 本のリストで表します。

```haskell
data Cell = Empty | Num Int
  deriving (Eq, Ord, Show)

type Board = [Cell]
type Pos   = Int
```

`Cell` は第 7 章の `data` 宣言です。マスは「空」か「数字入り」のどちらかで、その 2 つ以外の状態はありません。`Maybe Int` を使っても表せますが、`Empty` と `Num` という名前を付けたほうが、コードを読んだときに盤の話だと分かります。

1 本のリストにした理由は、本家のルールにある「行の終わりと次の行の始まりはつながっている」を自然に扱えるからです。添字 8(1 行目の右端)と添字 9(2 行目の左端)は、リストの上では隣どうしです。

位置から行と列を求めるには、割り算と余りを使います。

```haskell
rowOf p = p `div` 9
colOf p = p `mod` 9
```

## 消せる組の条件

2 つの数字が組になる条件は「同じ」か「和が 10」です。

```haskell
matches :: Int -> Int -> Bool
matches a b = a == b || a + b == 10
```

位置の条件は `connected` が担当します。添字 i と j (i < j) が次のどれかの直線上にあり、途中のマスがすべて空なら `True` です。

| 方向 | 添字の進み方 | 追加の条件 |
|---|---|---|
| 読み順(横、行末から次の行へ) | 1 ずつ | なし |
| 縦 | 9 ずつ | 列が同じ |
| 右下の斜め | 10 ずつ | 列の差 = 行の差 |
| 左下の斜め | 8 ずつ | 列の差 = −(行の差) |

斜めに「追加の条件」が要るのは、添字の差が 10 でも斜めとは限らないからです。たとえば添字 8(0 行 8 列)と添字 18(2 行 0 列)は差が 10 ですが、右下の斜めではありません。列の差を見るとこの偽物を弾けます。

```haskell
clear step =
  (j - i) `mod` step == 0
    && all (\p -> cellAt b p == Empty) [i + step, i + 2 * step .. j - step]
```

`[i + step, i + 2 * step .. j - step]` は第 4 章の等差数列の書き方で、i と j の間にあるマスの添字を step 刻みで並べます。`all` は第 6 章の高階関数で、その全部が空なら `True` を返します。

## 消せる組の一覧

```haskell
validPairs b =
  [ (i, j)
  | (i, Num a) <- indexed
  , (j, Num c) <- indexed
  , i < j
  , matches a c
  , connected b i j
  ]
  where indexed = zip [0 ..] b
```

第 4 章のリスト内包表記です。生成器のパターンを `(i, Num a)` にしているので、空マスは自動的に飛ばされます。`i < j` で同じ組を 2 回数えないようにしています。

## 消す、縮める、足す

```haskell
removePair i j b = [if p == i || p == j then Empty else c | (p, c) <- zip [0 ..] b]

collapseRows = concat . filter (not . all (== Empty)) . rows

addNumbers b = trimmed ++ map Num (numbers b)
  where trimmed = reverse (dropWhile (== Empty) (reverse b))
```

`collapseRows` は関数合成で書いた 3 段の処理です。右から読むと、盤を行に切り分け(`rows`)、全部空の行を除き(`filter`)、つなぎ直す(`concat`)。`rows` は第 5 章の再帰で書いてあります。

```haskell
rows [] = []
rows b  = take 9 b : rows (drop 9 b)
```

`addNumbers` は、末尾の空マスを詰めてから残りの数字を足します。`reverse` して `dropWhile` して `reverse` し直すのは、「末尾から空を取り除く」を手持ちの関数で表す定番の形です。

## パリティ不変量

追加なしで全消しできる盤には、必要条件があります。

1 手で消えるのは「d と d」か「d と 10−d」の 2 個です。数字を {1,9}、{2,8}、{3,7}、{4,6}、{5} の 5 つのグループに分けると、どの 1 手も 1 つのグループから 2 個減らします。つまり、各グループの個数の偶奇は 1 手ごとに変わりません。全消しした状態では各グループが 0 個(偶数)なので、最初から各グループが偶数個でなければ全消しできません。

```haskell
parityOk b = all even [count d + count (10 - d) | d <- [1 .. 4]] && even (count 5)
```

この条件から、すぐに分かることが 1 つあります。5 つのグループの個数をすべて足すと盤のマス数になります。偶数を 5 つ足した結果は偶数なので、マス数が奇数の盤は決して全消しできません。本家の初期盤は 27 個で、追加を使わない限りクリアできない設計です。このゲームでは 26 個から始めます。

この性質は `test/Spec.hs` で確かめています。ランダムな盤に対して、消せる組をどれか消しても `parityOk` の値が変わらないこと、27 マスの盤はすべて `parityOk` が `False` になることを検査します。

## JavaScript への移植

`web/js/rules.js` に同じ関数があります。Haskell と違うのは、`Cell` の代わりに 0(空)と 1〜9(数字)の整数を使う点です。JSON には型を書けないので、JSON と同じ表現に合わせました。読み比べると、リスト内包表記が二重の `for` に、`all` が `for` の途中での `return false` に変わっているのが分かります。
