# 02 解を探す

対象: `generator/src/NumberMatch/Solver.hs`。
対応する授業の章: 第 5 章(再帰)、第 6 章(高階関数)。`Data.Set` は授業の範囲外なので、ここで説明します。

## 何を保証したいか

「このボードは、追加なしで全消しできる」と言い切るには、実際に全消しする手順を 1 つ見つければ十分です。ソルバの仕事はその手順を探すことです。見つかれば `Just 手順`、予算内に見つからなければ `Nothing` を返します。

```haskell
solve :: Int -> Int -> Board -> Maybe [Move]
```

引数は調べてよい状態の数(予算)、使ってよい追加の回数、ボードです。

## 深さ優先探索

ボードを 1 つの「状態」と考えます。消せるペアを 1 つ選んで消すと、別の状態に移ります。全消しの状態にたどり着く道を探すので、これは迷路の探索と同じです。

深さ優先探索は1 本の道を行けるところまで進み、行き止まりなら 1 歩戻って別の道を試す方法です。再帰で自然に書けます。

```haskell
search budget adds b seen
  | isCleared b          = (Just [], budget, seen)         -- ゴール
  | budget <= 0          = (Nothing, 0, seen)              -- 予算切れ
  | Set.member key seen  = (Nothing, budget, seen)         -- 来たことがある
  | otherwise            = tryMoves (budget - 1) (Set.insert key seen) candidates
```

`tryMoves` は候補の手を順に試します。1 つ目の手で見つかればその結果を返し、見つからなければ次の手を試します。候補がなくなれば `Nothing` です。

```haskell
tryMoves bud s []       = (Nothing, bud, s)
tryMoves bud s (m : ms) =
  case search bud (addsAfter m) (applyMove m b) s of
    (Just rest, bud', s') -> (Just (m : rest), bud', s')
    (Nothing,   bud', s') -> tryMoves bud' s' ms
```

見つかった手順の先頭に今の手 `m` を足して返すところが、第 5 章の「再帰の結果を組み立てる」形です。

## 同じ状態を二度調べない

違う順番で消しても同じボードになることがよくあります。たとえば「A を消してから B」と「B を消してから A」は同じボードです。一度調べて駄目だったボードをもう一度調べると、時間を二重に使います。

そこで、調べたボードの集合を `Data.Set` に入れて持ち回ります。`Set.member` で「来たことがあるか」を調べ、`Set.insert` で記録します。どちらも要素数 n に対しておよそ log n の時間で済む操作です。リストで `elem` を使うと n に比例した時間がかかるので、状態が数万個になる探索ではこの差が効きます。

`Set` に入れる値には `Ord` のインスタンスが必要です。`Cell` に `deriving (Eq, Ord, Show)` を付けてあるのはこのためで、`Board` はそのリストなので自動的に `Ord` になります。

## 状態を「手渡し」する

`search` の返り値は 3 つ組です。見つけた手順のほかに、残りの予算と、調べた状態の集合を返しています。呼び出し側はそれを受け取って次の呼び出しに渡します。

これは面倒ですが、Haskell には変数の書き換えがないので、変わっていく値は引数と返り値で運ぶしかありません。この手渡しを隠してくれる道具が State モナドで、授業では第 11 章以降で扱います。このソルバを State モナドで書き直すと、`tryMoves` の分岐が `case` ではなく `do` の中の数行になります。先に手渡し版を読んでおくと、モナドが何を省略しているかが分かります。

## 手の順番が速さを決める

深さ優先探索は、最初に試す手が良ければすぐ終わり、悪ければ長くさまよいます。`orderMoves` で候補を並べ替えています。

```haskell
orderMoves b = sortOn key
  where key (i, j) = (length (applyMove (Remove i j) b), i, j)
```

`sortOn` は第 6 章の高階関数で、各要素に関数を当てた値の小さい順に並べます。ここでは「消した後のボードの長さ」を使っているので、行が消える手(ボードが 9 短くなる)が先に来ます。行を消すと残りの探索が小さくなるからです。同点ならボードの上のほうの手を先にします。

消せるペアがあるうちは追加を試さない、という制限も入れています。追加はボードを倍に増やすので、探索が爆発しやすいからです。この制限のせいで解を見逃すボードはありえますが、生成では「追加 0 回」のボードだけを採用しているので影響はありません。

## 予算は難易度の目盛りでもある

`budget` は調べてよい状態の数で、生成では 4000 にしています。はじめは 60000 にしていましたが、見つからないボードで予算を使い切ると 1 枚あたり数秒かかり、面の生成が終わりませんでした。

4000 に下げても面は十分見つかります。しかも、小さな予算で見つかるボードは「行消し優先の素直な手順で解けるボード」なので、人にも筋道が見つけやすいボードです。予算の大きさを難易度の目盛りとして使えます。

## 検査

`test/Spec.hs` では、ソルバが返した手順を `replay` でボードに適用し、本当に空になることを確かめています。

```haskell
replay = foldl (flip applyMove)
```

第 6 章の `foldl` です。手順の先頭から順に `applyMove` を当てていきます。引数の順が逆なので `flip` を挟んでいます。
